# Venture Route web app

React 19 + Vite + TypeScript strict, Tailwind v4 with the DESIGN.md tokens, shadcn/ui, react-router 7,
vite-plugin-pwa, and `@clerk/react` for accounts. It talks only to the FastAPI engine and renders
`VentureRoute` objects; the browser never parses MeTTa output. Every screen replicates the approved
Stitch export under `design/stitch/` (D-36).

## Run

```bash
pnpm install                                   # repo root
pnpm --filter @venture-route/contracts build   # the app imports the built contracts package
pnpm --filter web dev                          # http://localhost:5173
```

The dev server proxies `/api` and `/health` to `VITE_API_URL` (default `http://localhost:8000`),
so start the engine first (`services/engine`: `uv run uvicorn app.main:app --reload`). Production
builds call `VITE_API_URL` directly and rely on the engine's `CORS_ORIGINS` allow-list.

| Variable | Effect |
|---|---|
| `VITE_API_URL` | Engine base URL. |
| `VITE_CLERK_PUBLISHABLE_KEY` | Enables Clerk. Empty or the `.env.example` placeholder mounts the app without Clerk: routing works, account screens show "Sign-in is not configured". |
| `VITE_OFFLINE_DEMO=1` | Serves the five seed routes from `src/offline/snapshot.json` (generated by the engine's `export_offline_snapshot.py`) for the recorded fallback. |

## Routes

| Path | Screen | Access |
|---|---|---|
| `/` | Landing page | public |
| `/route` | Intake (chat or `?mode=form`) → brief review → route result with gaps above team cards and the "Why this route?" drawer | public |
| `/handoff` | Plain-text venture handoff (copy, download) | public |
| `/sign-in`, `/sign-up` | Stitch sign-in frame around Clerk's prebuilt components | public |
| `/choose-role` | Founder / builder cards; posts `POST /api/me/role` once | signed in |
| `/profile`, `/profile/projects/new` | Builder profile, availability, credentials, projects | role `builder` |
| `/builders/:builderId` | Candidate profile with shared contact only | role `founder` or `admin` |
| `/admin` | Confirmation queue with `projected_rows` after each decision | role `admin` |

`RequireRole` reads Clerk `publicMetadata.role`: signed out → `/sign-in`, no role → `/choose-role`,
wrong role → that role's home (`/route`, `/profile`, `/admin`).

## Structure

```text
src/api/         client.ts (one fetch wrapper; Zod-parses every response; bearer token only on /api/me, /api/admin, /api/builders),
                 marketplace.ts (profile, proof, candidate, admin calls), offline.ts, default.ts (api vs offline)
src/auth/        Clerk provider or no-key provider behind one AuthState, RequireRole, ROLE_HOME
src/state/       reducer-and-context routing store (scenarios, brief, turns, last route, view)
src/features/    landing, intake, review, route, why, handoff, auth, builder, candidate, admin
src/components/  TopNav, SiteFooter, DemoDataPill, banners; ui/ is shadcn output (edit through the CLI only)
src/lib/         formatting, brief helpers, next actions, validation-error mapping
src/styles/      tokens.css from the Stitch DESIGN.md block
test/            Vitest + React Testing Library through rendered screens; fakeEngine.tsx fakes fetch
e2e/             Playwright flows against vite preview with the engine on LLM_PROVIDER=null
```

## Test

```bash
pnpm --filter web test        # Vitest, jsdom
pnpm --filter web typecheck
pnpm --filter web lint
pnpm --filter web e2e         # builds, starts the engine and two previews (4173 online, 4174 offline), runs Playwright
```

Tests render `<App initialPath="…" source={…} auth={…} marketplace={…} />`: the routing source, the
auth state and the marketplace API are injected, so Clerk never loads in jsdom and no test reaches
a network. Seams are fixed per sprint (D-19): rendered screens and Playwright flows only, no
component-internal or markup-snapshot tests. The Playwright suite runs without a Clerk key; the
three-role sign-in smoke uses Clerk test users locally and pastes its output as evidence.

## Rules the UI enforces

- Gaps render above any builder card (AGENTS.md rule 6); tested with `compareDocumentPosition`.
- Every seed-derived or user-entered record shows the Demo data pill (rule 5).
- A self-described skill renders "Self-described · display only" and is never shown as verified (rule 4); the engine decides `status` and `evidence`.
- The Technical view of "Why this route?" renders `ReasoningPath` objects only (D-31); handoff text is built client-side by `handoffText(brief, route)` and never includes the model's summary.
- Stitch embellishments that assert capabilities the product lacks (ledgers, hashes, attestations) are left out and listed in the sprint report (rule 10).
